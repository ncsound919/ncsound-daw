# Plan 07-01 — Render digest characterization test

**Objective:** Pin the engine's exact rendered output as a hash **before** a single line moves, so
every later plan can prove it changed no sample.

This is the only plan in the phase permitted to add a test that asserts on a magic number captured
from current behaviour. That is the point: the number *is* current behaviour.

```cpp
#include <catch2/catch_test_macros.hpp>
#include "AudioEngine.h"
#include <bit>
#include <cstdint>

namespace
{
constexpr int kBlockSize = 512;
constexpr int kBlocks = 96;      // 1.024 s at 48 kHz
constexpr int kTrackCount = 8;

std::uint64_t digestOf (nc::AudioEngine& engine)
{
    std::uint64_t hash = 0xcbf29ce484222325ull;          // FNV-1a 64 offset basis
    constexpr std::uint64_t prime = 0x100000001b3ull;
    juce::AudioBuffer<float> out (2, kBlockSize);
    for (int block = 0; block < kBlocks; ++block)
    {
        out.clear();
        float* channels[2] { out.getWritePointer (0), out.getWritePointer (1) };
        engine.processBlockForTesting (nullptr, 0, channels, 2, kBlockSize);
        for (int ch = 0; ch < 2; ++ch)
            for (int i = 0; i < kBlockSize; ++i)
            {
                const auto bits = std::bit_cast<std::uint32_t> (out.getSample (ch, i));
                hash ^= bits;
                hash *= prime;
            }
    }
    return hash;
}
} // namespace

TEST_CASE ("engine render digest is stable", "[digest]")
{
    nc::AudioEngine engine;
    engine.setBpm (128.0);
    engine.setActiveTrackCount (kTrackCount);
    engine.setMetronome (false);
    engine.setLoopEnabled (false);

    std::vector<nc::AudioEngine::TimelineClip> clips;
    for (int track = 0; track < 4; ++track)
    {
        nc::AudioEngine::TimelineClip clip;
        clip.assetId = engine.demoAssetId (track);
        clip.track = track;
        clip.startBar = 1.0;
        clip.lengthBars = 4.0;
        clips.push_back (clip);
    }
    REQUIRE (engine.setTimelineClips (std::move (clips)) == 0);

    engine.setTrackGain (0, 0.7f);
    engine.setTrackPan (1, -0.4f);
    engine.setTrackSendA (0, 0.5f);
    engine.setTrackSendB (2, 0.25f);
    engine.setTrackWidth (3, 0.75f);
    engine.setMasterGain (0.8f);

    nc::AutomationLane lane;
    lane.addPoint (0.0, 0.25f);
    lane.addPoint (16.0, 0.9f);
    engine.setTrackAutomation (0, nc::AutomationParam::Volume, lane);

    juce::Thread::sleep (300);              // let the device prepare a rate
    engine.suspendAudioCallbackForTesting();

    // The digest is captured from the current code on the first run and pinned
    // here; every later refactor step must reproduce it exactly.
    const auto digest = digestOf (engine);
    INFO ("render digest: 0x" << juce::String::toHexString (static_cast<juce::int64> (digest)));
    REQUIRE (digest == 0x0000000000000000ull);   // placeholder, replaced in task 01.2
}
```

Match the existing test style: 4-space indent, `.cpp`, no `using namespace`. The API above is

filled with `addPoint (double beats, float value)`, and `points` is a private fixed array — never
touch it directly. Do not change `Automation.h`.

## Result (2026-11-14)

Landed as `app/Source/RenderDigestTests.cpp`, registered in the `NCMixRackTests` target.

Two deliberate deviations from the draft action above:

- **Silent stereo input instead of `nullptr`.** `processBlockForTesting` forwards straight to
  `renderBlock`; zero input channels was never exercised by an existing test, and this test should
  pin the mix, not null handling.
- **A 32-block warm-up that is not hashed.** The fader and master smoothers need ~16k samples to
  converge and the aux tails decay exponentially, so hashing from block 0 would let the digest
  depend on what the constructor's device rendered before the callback was detached.

Captured digest: `0x1b5398dd4a9f297a`. Three consecutive runs pass, `-s` prints the same value
every time, and the full suite is 195/195.

## Risks

- If the first run's digest is unstable, the cause is almost always a live audio device still
  attached (including the constructor's automatic device open) or an unseeded noise source. Fix
  the test's setup order, never the engine.
- `demoAssetId (track)` is only populated for `demoTrackCount` tracks; if a future change makes the
  demo content lazy, the digest test is the thing that will catch it.
