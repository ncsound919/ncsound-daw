# Plan 07-07 — `MainComponent`: command table and split

**Objective:** 2736 lines → six files, and replace the 744-line `handleMenuResult` switch with a
table that `openMenu` also reads, so the two 80-item lists can never drift apart again.

## Why the table, not just a split

`openMenu` declares **84** items; `handleMenuResult` has **86** `case` labels. Splitting the switch
across files would hide that mismatch, not fix it. One table with `{id, label, enabled-predicate,
handler}` makes a missing handler a compile error and a missing label visible in one diff.

Menu ids are already stable 4-digit integers: `1001-1099` session/export/agent, `2001+` edit/MIDI,
and so on. **The ids must not change** — they are what JUCE's async menu callback returns.

<action>
In `MainComponent.h`, under `private:`, add:

```cpp
struct MenuCommand
{
    int id;
    const char* label;
    void (MainComponent::*run)();
    bool (MainComponent::*enabled)() const;   // nullptr = always enabled
};

/** One row per menu item. openMenu() and handleMenuResult() both read this,
    so an item without a handler is a compile error and a handler without an
    item is a dead row nobody can add twice. */
static const std::array<MenuCommand, N>& menuCommands();
```

and the handler declarations the table needs. Split every multi-statement `case` body into a named
private method whose body is the case body moved verbatim (e.g. `case 1002:` becomes
`void openSessionDialog()`, `case 1004:` becomes `void mixdownWav()`, and so on). Cases that already
call one method keep that method as the handler.

Then in `app/Source/MainComponentMenus.cpp`:
- `menuCommands()` returns a `static const std::array` with **one row per existing `case` label**,
  in ascending id order, `label` copied verbatim from the matching `menu.addItem` string.
- `openMenu` builds items from the table; section headers stay as explicit
  `addSectionHeader` calls in the same places they are today.
- `handleMenuResult (int result)` becomes:

```cpp
for (const auto& command : menuCommands())
    if (command.id == result) { (this->*command.run)(); return; }
```

Rules:
- No id changes. `git diff` must show every original 4-digit literal still present exactly once as
  a table `id`.
- `enabled` points at the predicate the current `addItem (id, "label", predicate)` already passes
  (`arrange.canUndo()`, `arrange.hasSelectedClip()`, …). Where the item is unconditional, `nullptr`.
- Item order in each submenu must match today's order exactly.
</action>

## Risks

- **Async handlers.** Several cases capture `juce::Component::SafePointer<MainComponent>`; turning a
  case body into a method must keep the capture inside the method, not hoist it to the table.
- **`result == 0`.** JUCE returns 0 when a menu is dismissed. The table loop must leave that a no-op,
  which it does — but do not "fix" it with a default case that calls anything.
- **`menuAt` and `mouseDown`.** The custom header hit-test opens the menus; if `menuAt` lands in the
  paint TU but `mouseDown` stays behind, the two must still agree on the same geometry constants.
