# Plan 07-03 — Split `AudioEngine.cpp` into translation units

**Objective:** 4564 lines → eight files, none over ~900, with `AudioEngine.h` byte-identical and
`AudioEngine.cpp` ending near 350 lines. Stage A of D-01: bodies move, the class does not.

**Rule for every task in this plan:** cut the function body from `AudioEngine.cpp` and paste it
unchanged into the target file. The only edits permitted are (a) adding the new file's `#include`
block, (b) moving the anonymous-namespace helpers into the internal header, (c) nothing else.

After every task: build, run the guard, run `ctest`. Any red result stops the plan.

### The mix_rack 2.1x — machine state, not the split

`mix_rack` is `add_test(NAME mix_rack COMMAND NCMixRackTests)`, the whole binary, so it measures
the full suite rather than one engine loop. It read 210 s before the split and 447 s after, which
looked like a 2.1x regression.

It is not. Splitting the file did not change the render cost:

| Build | `AudioEngine.cpp` | mix_rack |
|---|---|---|
| `fb2154d` in a git worktree (pre-split) | 4564 lines, 1 TU | **457 s** |
| `b6e6132` (split) | 381 lines, 10 TUs | **447 s** |

Both are `Release`/Ninja builds, both run back to back on the same machine on 2026-11-15, each
with 118 cases and 55670 assertions. The pre-split code is the slower of the two by 10 s, so the
2.1x is machine state (thermal or background load), not the decomposition. The 210 s figure does
not reproduce on this machine today even with the original single-translation-unit code.

Two theories were raised and both are dead:

- **Per-sample readers losing inlining.** `sampleAt`, `readSourceSample` and `readBandLimited` were
  moved back alongside `renderBlock`; the time went 440 s -> 447 s. No effect. They are kept there
  on their merits, not for the 7 s.
- **A single pathological test.** The cost is spread evenly: the slowest case is 31 s of 447, and
  render-heavy cases scatter between x0.45 and x4.2 run to run.

The control build needed two workarounds, both environmental: `core.autocrlf=true` rewrote line
endings in the fresh worktree and broke the ChordStudio SHA256 lock (`cmake/ChordStudioDeps.cmake`),
and `ui/dist` is untracked so configure refused (`app/CMakeLists.txt`). Neither touches the C++
inputs.

### Cleanup after the mechanical move

The extractor leaves debris behind, and it was cut:

- **Sixteen dead includes.** Removal was driven by symbol use per unit, not by habit:
  `AudioEngine.cpp` went from 14 includes to 6, because once only the ctor, track parameters,
  voice-to-MIDI and the test hooks remained, `AudioEngineInternal.h`, `BuiltinStudioFx.h`,
  `BuiltinSynth.h`, `ClipTimeline.hpp`, `MidiSchedule.hpp`, `ProjectLimits.hpp`, `StreamWindow.hpp`
  and `<cmath>` were no longer referenced. `AudioEngineInternal.h` also left export, assets,
  transport, plugins and recording and stays only in device, demo and render, which use
  `audioPropsOptions`, `twoPi` and the tone probe. `<thread>` left export, assets and recording.
- **A blank line after every `namespace nc {`** — an artifact of the extractor's chunk boundary, not
  the original house style. Removed from all eight extracted units; `AudioEngine.cpp` keeps its
  original header and opening.

After the cleanup: `move-only: 303 definitions checked, 0 missing`, digest still
`0x1b5398dd4a9f297a`, both targets link, and the full test binary passes 118 cases / 55670
assertions with exit 0. One ctest run reported 194/195 because its 1501 s per-test cap expired on
`mix_rack` while other sessions' dev servers were saturating the machine; the same binary passes
when run directly, and the 194 individual tests passed in both runs.

The extractor scripts stay in `build/` (`split-engine.mjs`, `move-samples.mjs`) as the record of how
the bodies were moved, since neither is tracked.


## Risks

- **Missing a file in one target.** `AudioEngine.cpp` is compiled into `NCMixRackTests` and
  `NCSoundHub`. A new TU added to only one target produces an undefined-symbol link error in the
  other — which the build catches, but only if both targets are built. `_ncbuild_ok.cmd` builds
  both, so always use it.
- **`inline` helpers and duplicated state.** If `dumpStage`'s static sinks or `toneProbe`'s static
  probe end up in more than one TU, behaviour changes silently. The digest will not catch the
  dump-file duplication. Diff `AudioEngineInternal.h` against the lifted block line by line.
- **Link-time codegen.** Splitting translation units can change inlining across the former
  boundaries and therefore the last bit of a float. If the digest moves by a few ULPs, do not
  "re-pin" it: report it. A tolerance policy is a decision, not a cleanup.
