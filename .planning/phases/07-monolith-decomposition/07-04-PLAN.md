# Plan 07-04 — Decompose `renderBlock`

**Objective:** `AudioEngine::renderBlock` is 741 lines. It already has four named passes in its
comments. Make each pass a private method so a reader can see the block's shape in one screen.

This is the highest-risk plan in the phase: it is the only one that rearranges real-time code.
The digest test is the gate, and it must be unchanged at every step.

**Line numbers below are approximate and will drift — locate passes by the `// Pass N:` comment
text, never by line number.**

## Current shape

| Region | Contents |
|---|---|
| preamble | denormal scope, pending reset/seek, smoother priming on play transition, tempo snapshot, buffer sizing, clip-prep loop |
| `// Pass 1:` | render clips into one stereo lane per track |
| `// Pass 2:` | MIDI scheduling, instrument render, insert chain, PDC, per-block automation evaluation |
| `// Pass 3:` | native strip, fader/pan, click, master gain |
| `// Pass 4:` | aux returns, master rack, monitor (mono/dim), soft limit, peak metering |

## Risks

- **An early `return` moved across a pass boundary.** `renderBlock` has conditional early-outs for
  `offlineRender` and device-not-open. If one of those ends up inside a pass instead of before the
  four calls, a silent device either renders twice or not at all. The digest catches the audible
  case; the offline-render case may not be covered — check `ExportTests` explicitly after 04.1.
- **Per-block snapshots.** Pass 3 deliberately snapshots fader-adjacent atomics once per block
  (comment at the top of the pass). Do not spread those reads back into the per-sample loop while
  moving code — that is exactly the ~80 atomic loads/sample the comment says was fixed.
- **`smoothed*` arrays and `smoothingPrimed` are primed in the preamble.** Their lifetime must stay
  in `renderBlock`, before pass 1, or the first block of every play ramps from unity and the
  maximizer crack returns.
