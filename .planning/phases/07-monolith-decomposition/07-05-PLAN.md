# Plan 07-05 — Extract `AssetLibrary` and `TransportClock`

**Objective:** Stage B. Two real classes with their own headers, following the pattern already
proven by `TrackInsertRack.h`: message-thread ownership, audio-thread reads through atomics, retired
buffers freed by block counter.

`AudioEngine` keeps every public method. It forwards. Callers and tests do not change.

## Why these two, and only these two

`AssetLibrary` is storage plus the sample-read path — it has no idea what a track is.
`TransportClock` is tempo, position, loop and markers — it has no idea what a plugin is.
Both have a single audio-thread entry point and a message-thread API, which is the shape
`TrackInsertRack` already demonstrates. Everything else in the engine is genuinely
track-centric or insert-centric and would need a back-reference to the engine, which is worse
than the status quo.

## must_haves

- **truths**
  - `AudioEngine`'s public API is unchanged; no test file edited.
  - `AssetLibrary` never allocates on the audio thread.
  - `TransportClock::advance` returns the same position the inline code did, loop wrap included.
  - Digest unchanged.

## Risks

- **`AudioAsset` is referenced by value inside the render scratch (`RenderClip` holds
  `const AudioAsset*`).** Renaming to `AssetLibrary::Asset` touches `PlaybackClip` and `RenderClip`
  too. Do it as one mechanical rename, then compile.
- **`retireSnapshot` becoming shared.** It is a template; moving it into a header that both classes
  include is fine, but it must not gain a second static.
- **`audioBlockCount` ownership.** It is incremented on the audio thread and read by both
  retirement lists. If `TransportClock` takes it and `AudioEngine`'s insert rack keeps its own
  counter, the two can retire at different times. Keep `TrackInsertRack`'s internal counter
  independent (it already is) and pass the engine's counter value into both `reclaim` calls.

Two deliberate interface deviations, both to keep behaviour identical:

- `TransportClock::block (double sampleRate, int blockSize)` instead of the placeholder signature
  above: the moved `transportBlock` body derives its loop bounds from the tempo map rather than
  taking a `nearsLoopEnd` flag, so the flag had no meaning to carry.
- **`advance (int numSamples, bool& loopWrapped)` is not extracted.** The position advance is one
  `++position` per sample, interleaved with clip rendering inside the pass 1 loop, and the loop
  wrap also resets the engine's click state. Hoisting it to a per-block `advance` would move the
  transport between samples and change the digest. The clock owns the atomic instead: the pass
  advances its own `int64_t`, wraps at the loop point exactly as before, and publishes once with
  `storePosition`. That is the same arithmetic at the same point in the block.

`AssetLibrary::refreshResampleBanks` and `serviceStreaming` take the output rate (and the transport
position) as parameters rather than reaching back into the engine.

The move-only guard reports the `AudioEngine` constructor as changed, because its two tempo-seeding
lines now live in `TransportClock`'s constructor, which builds the same 120 BPM map.
