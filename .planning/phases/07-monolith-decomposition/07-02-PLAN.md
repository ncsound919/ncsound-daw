# Plan 07-02 — Move-only guard

**Objective:** A check that proves a "move bodies into another file" step relocated function
bodies **verbatim**. Without it, the two UI files — which have no C++ tests at all — could lose a
line in a move and nobody would notice until a user clicked the wrong thing.

The digest test (07-01) covers DSP. This covers everything else.

## Design

`scripts/verify-move-only.mjs`, run with `node` (already used by `scripts/gen-native-routes.mjs`).

Two modes:

| Mode | Flag | Proves |
|---|---|---|
| move | `--base <ref>` | every function body that existed at `<ref>` exists today, byte-identical after whitespace removal, somewhere under `app/Source/` |
| decompose | `--base <ref> --preserve-order <Name>` | every statement of the base function `<Name>` appears, in the same relative order, across today's files |

Mode `move` is used by the pure-relocation plans (07-03, 07-06, 07-07).
Mode `decompose` is used by 07-04, where `renderBlock` is legitimately cut into four methods.

<action>
Create `scripts/verify-move-only.mjs`. Node ESM, no dependencies, `node:child_process` +
`node:fs`.

**1. `readAt (ref, path)`** — `git show ${ref}:${path}`, returns a string. On non-zero exit, throw
`base ref ${ref} has no ${path}`.

**2. `extractDefinitions (text)`** — returns `[{ name, body }]`:
- Iterate lines. A *candidate* start is a line at column 0 matching
  `/^[A-Za-z_][A-Za-z0-9_:<>,*&\s]*::[A-Za-z_~][A-Za-z0-9_]*\s*\(/` (member definitions) or a line
  at column 0 inside a leading `namespace {` block matching
  `/^[A-Za-z_][A-Za-z0-9_:<>,*&\s]*\s+[A-Za-z_][A-Za-z0-9_]*\s*\(/` (the free helpers
  `softLimit`, `toneProbe`, `dumpStage`, `audioPropsOptions`).
- Skip candidates whose line ends in `;` (declarations).
- From the start line, scan forward to the first `{`. Then brace-count to the matching `}` while
  ignoring braces inside string literals, char literals and `//` comments. String literals matter:
  `handleMenuResult` contains item text.
- `name` = the signature text from the start line up to `(`, whitespace-collapsed. `body` = the
  text from the opening `{` through the matching `}` inclusive.

**3. `normalize (s)`** — `s.replace(/\s+/g, '')`. Whitespace-insensitive, token-exact.

**4. `collectWorkingTree()`** — every `app/Source/*.cpp` and `app/Source/*.h`, concatenated.

**5. Mode `move`:**
- For each base definition, look for `normalizedBody` as a substring of the normalized working-tree
  text.
- Collect misses. For a miss, print the base function name and the first 120 characters of its
  normalized body so the reader can find it.
- Exit 0 only when the miss list is empty. New functions are never reported.

**6. Mode `decompose --preserve-order <Name>`:**
- Take the base definition whose name contains `<Name>` as a substring (so `renderBlock` matches
  `void AudioEngine::renderBlock `).
- Split its body into statements at top-level `;` and `{...}` boundaries, normalize each, drop
  empties.
- Walk that list in order through the normalized working-tree text, consuming a cursor as each
  statement is found. If a statement is not found ahead of the cursor, report it and the index.
- Exit 0 only if all statements were found in order.

**7. CLI** — `--base <ref>` required; `--paths <a b c>` optional (default
`app/Source/AudioEngine.cpp app/Source/ArrangeView.cpp app/Source/MainComponent.cpp`);
`--preserve-order <Name>` optional. Print a one-line summary:
`move-only: <n> definitions checked, <m> missing` or `decompose: <Name>, <n>/<total> statements in order`.

Keep it under ~140 lines. It is a checker, not a tool: no config file, no flags beyond the above.
</action>

</task>

## Verification

```
node scripts/verify-move-only.mjs --base HEAD          # exit 0
node scripts/verify-move-only.mjs --base HEAD~1        # exit 1 (proves it detects change)
```

## must_haves

- **truths**
  - A single edited token inside any pre-existing function body fails the check.
  - Whitespace and line-ending changes (CRLF → LF, which this repo mixes) do not fail the check.
  - The check reads the baseline from git, so it still works after the source file is shortened.

## Result (2026-11-14)

`scripts/verify-move-only.mjs` landed and is proven in both modes against the current tree:

```
move-only: 307 definitions checked, 0 missing          (--base HEAD)
decompose: renderBlock, 75/75 statements in order      (--base HEAD --preserve-order renderBlock)
```

A one-line probe inserted inside `AudioEngine::saveAudioSettings` made it exit 1, naming that
function; the file was then reverted with `git checkout` and the check returned to 0 missing.

Two implementation notes that matter for later plans:

- **Functions live inside `namespace nc {`.** A depth-0-only parser finds nothing (the first draft
  reported "0 definitions checked"). The scanner tracks brace frames with a stack and takes the
  signature from the last `;`/`{`/`}` boundary at the enclosing depth.
- **`--base a4f1ab3` is not a usable negative control.** `AudioEngine.cpp` is unchanged since that
  commit, so it passes legitimately. Prove failure with a temporary edit, as above.

Statement splitting tracks parentheses as well as braces, so `for (int i = 0; i < n; ++i)` does not
split mid-header.

## Risks

- Brace counting inside `String` literals is the one place this can go wrong. `MainComponent` has
  menu labels with `{}`-free text today; the string-literal skip is still mandatory because the
  project file writer emits JSON containing braces.
- If `git show` is unavailable in a worktree, pass an explicit sha rather than `HEAD`.
- The check is stricter than "behaviour identical": adding a comment inside a body fails it. That
  is intentional — a move-only step must be a pure move.
