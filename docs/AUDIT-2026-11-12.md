## 1. Verdict

The architecture is sound and in most places unusually careful: lock-free snapshot publishing, crash containment for third-party DSP, a JUCE-free header-only engine, path-traversal and JSON-bomb defence in the project loader, and a single generated bridge contract.

The working tree is nevertheless **not buildable as committed**, the full native suite is **red**, and one hot path still violates the engine's own "no allocation on the callback" rule.

### DAW-01 — Critical — the working tree does not compile

`app/Source/AudioEngine.cpp:2313-2319` (error reported at 2317)

```cpp
// TEMP DIAGNOSTIC: per-stage wall-time accumulation while NC_STAGE_TIMER=1.
struct StageStats
{
    static constexpr int count = 8;              // C2246
    std::atomic<int64_t> ticks[count] {};
```

`StageStats` is a local class, and C++ forbids static data members in local classes:

```
AudioEngine.cpp(2317): error C2246: 'nc::AudioEngine::renderBlock::StageStats::count':
illegal static data member in locally defined class
```

This is why the Release `.exe` (built 10:56) predates the last source edit (10:57). Every native gate in the work log refers to an older tree.

**Fix:** `enum { count = 8 };`, or move the struct to file scope, or delete the diagnostic (DAW-17). I verified it is the *only* compile error: with that single line changed, the Release build of `NCMixRackTests`, `NCSoundHub` and `NCScannerProbe` links clean (`BUILD_EXIT=0`).

### DAW-02 — High — `mix_rack` fails: voice-to-MIDI returns a non-MIDI clip on the error paths

`app/Source/AudioEngine.cpp:328-347` (`analyzeVoiceFile`), test at `app/Source/VoiceToMidiTests.cpp:89`

```
transcription of a missing file reports why, without throwing
VoiceToMidiTests.cpp(89): FAILED:
  REQUIRE( clip.isMidi )
with expansion: false
Catch will terminate because it needed to throw an exception.
Exit code 0xc0000409
```

`analyzeVoiceFile` returns `{}` on each failure path (unreadable file, short read, no notes). A default `ClipState` has `isMidi = false`, so the caller cannot tell a failed transcription from an audio clip, while the test's contract expects an empty *MIDI* clip plus an error string. The failure aborts the whole `mix_rack` binary, so every test after it in that suite never runs.

This slipped because the work log's last run explicitly excluded the suite it lives in: "ctest 165/165 (mix_rack excluded from the quick pass as a 5-minute suite; engine/audio/record/voice suites green)". `VoiceToMidiTests.cpp` is compiled into `NCMixRackTests`, not into the engine suite, so the excluded run was the only one that could have caught it.

**Fix:** set `clip.isMidi = true; clip.track = track;` before each early `return {}` (all three sites), or relax the test if "not a MIDI clip" is the intended contract — but pick one, because right now the suite is red.

### DAW-03 — High — heap allocation on the audio thread, once per track per block

**Status:** fixed — see §8.

`app/Source/AudioEngine.cpp:2709`

```cpp
for (int trackIndex = 0; trackIndex < trackCount; ++trackIndex)
{
    ...
    if (isPlaying && midiClipsPtr != nullptr)
    {
        juce::MidiBuffer midi;           // constructed per track, per block
        ...
        midi.addEvent (juce::MidiMessage::noteOn (...), event.sampleOffset);
```

`juce::MidiBuffer` owns a `juce::Array<uint8>`; `addEvent` calls `data.insertMultiple(...)`, which grows that array. Because the buffer is constructed inside the loop and destroyed each iteration, every playing block performs up to 64 allocate/free pairs — roughly 24k per second at 48 kHz/128 samples. That contradicts the guarantee stated in `AudioEngine.h` ("reserved once in `audioDeviceAboutToStart` so renderBlock never allocates") and the design note in `ProjectLimits.hpp`.

**Fix:** hold one `juce::MidiBuffer` as a member, `ensureSize` it once when the device starts, `clear()` per track.

### DAW-04 — High — every state push rescans all waveform data

**Status:** fixed — see §8.

`app/Source/WebViewBridge.cpp:256` (`buildState`) → `:312` (`engine.assetPeakEnvelope`) → `app/Source/AudioEngine.cpp:2067`

`buildState()` is the reply of almost every route (39 call sites) and recomputes a 96-bin peak envelope for **every audio clip** each time. `assetPeakEnvelope` walks the clip's samples across all channels — cost ≈ the clip length per call. So a mixer knob commit (300 ms debounce), a clip drag, a mute toggle or an automation edit each rescans the entire timeline's audio on the message thread, for data that has not changed. With the eight demo clips this is a few milliseconds; with a real session it is tens to hundreds of milliseconds per interaction.

**Fix:** cache the envelope per `(assetId, sourceOffset, length, bins)` and invalidate on asset add/remove and clip edit; or send peaks only on the routes that can change them. `buildTransport()` already shows the pattern for keeping high-frequency pushes small.

### DAW-05 — High — unbounded memory from a file header, and unchecked allocation

**Status:** fixed — see §8.

`app/Source/AudioEngine.cpp:1393` in `loadAudioFile`

```cpp
const auto frames64 = nc::limits::clampAssetFrames (sourceFrames, fileRate);
const auto frames = static_cast<int> (frames64);
...
asset->buffer.setSize (channels, frames);
```

`maxAssetSeconds` is 30 minutes *at the file's own rate*, bounded only by the `8000..192000` sanity band. A file claiming 192 kHz therefore allows 345.6 M frames → `setSize` attempts ≈ 2.7 GB (stereo float). The result is not checked, and an allocation failure throws `std::bad_alloc` on the message thread with no handler. A corrupt or hostile header is enough to make the app thrash or die.

Related: `maxProjectJsonBytes` is 256 MB, and `loadProjectDocument` materialises the file three times (`juce::String` → `std::string` → a `json::Value` tree of up to 1 M values) — roughly 1 GB transient for a maximal file.

**Fix:** cap the RAM path by *bytes* (e.g. 512 MB) rather than seconds-at-rate, stream above it, and catch `bad_alloc`/`length_error` to report "file too large". A 32–64 MB project cap is ample when plugin state is already capped at 2 MB per slot.

### DAW-06 — Medium — mixdown reserves the whole export in RAM

**Status:** fixed — see §8.

`app/Source/AudioEngine.cpp:3663-3664`

```cpp
leftBuffer.reserve (static_cast<size_t> (lengthFrames));
rightBuffer.reserve (static_cast<size_t> (lengthFrames));
```

The two-pass loudness design keeps the entire render in memory: 30 minutes at 48 kHz ≈ 690 MB, at 96 kHz ≈ 1.4 GB, at 192 kHz ≈ 2.7 GB. `reserve` can throw; the `RestoreSession` guard restores transport state but does not survive termination.

**Fix:** prime the loudness pass from a temporary file or bounded ring, or lower the ceiling at high rates and say so in the error message.

### DAW-07 — Medium — `webEditClip` casts untrusted doubles without finite/range checks

**Status:** fixed — see §8.

`app/Source/ArrangeView.cpp:1397-1414`

```cpp
if (obj->hasProperty ("startBar"))
    clip.startBar = juce::jmax (1, (int) std::round ((double) obj->getProperty ("startBar")));
if (obj->hasProperty ("lengthBars"))
    clip.lengthBars = juce::jmax (1, (int) std::round ((double) obj->getProperty ("lengthBars")));
```

The bridge guards most numeric routes with `finiteOr`, but this one takes the raw `juce::var`. `NaN` or an out-of-`int` value is undefined behaviour in the cast (CWE-681), and both fields are unbounded above — only the lower bound is clamped, so `lengthBars = 2e9` produces a clip no other layer expects.

**Fix:** use the bridge helper, clamp `startBar` to `1..maxBars`, `lengthBars` to `0..maxBars`, and keep `startBar + lengthBars` inside the timeline.

### DAW-08 — Medium — voice-to-MIDI copies the whole clip on the message thread

**Status:** fixed — see §8.

`app/Source/WebViewBridge.cpp` (`transcribeClip`) → `app/Source/AudioEngine.cpp:2027` (`assetSamples`)

The route builds a mono copy of the audio the clip plays *before* spawning the worker, then moves it into a detached `std::thread`. A 10-minute clip at 48 kHz is a 115 MB copy plus a full sample loop on the UI thread before the spinner starts, and every click spawns another detached thread with no concurrency limit or cancellation.

**Fix:** pass the asset id and range to the worker and copy there; keep one transcription in flight.

### DAW-09 — Medium — the React workspace caps at 8 tracks; the engine supports 64

**Status:** fixed — see §8.

`ui/src/App.tsx:17`, `ui/src/workspace/Workspace.tsx:99`, `:173`, `:749`

```ts

```

`nc::limits::maxTracks` is 64 and `defaultActiveTracks` is 16; the bridge normalises `setActiveTrackCount` to 1..64. A 16-track project opens and renders 16 strips, but "Add track" is disabled at 8. ### DAW-10 — Medium — `TrackInsertRack::collectGarbage`'s guard is not a barrier

**Status:** fixed — see §8.

`app/Source/TrackInsertRack.cpp:412-414`

```cpp
if (audioInCallback.load (std::memory_order_acquire))
    return;
```

`audioInCallback` is only set inside `beginBlock()`. A message-thread GC pass can observe `false` in the window before the callback reaches `beginBlock`, then destroy a retired processor. Today this is probably benign because slot pointers are unpublished before ownership moves, so a callback starting in that window reads `nullptr` or the new processor — but that is a timing argument, not a guarantee, and it is the same class of bug the snapshot code solves properly with the `retiredAtBlock + 2` rule (`AuxBus::collectRetired`).

**Fix:** retire rack slots by block counter, like tempo/MIDI/automation snapshots.

### DAW-11 — Medium — `AnalogCharacter`'s two-slot snapshot can tear on three writes per block

**Status:** fixed — see §8.

`engine/include/nc/engine/AnalogCharacter.hpp` (new `setSettings`/`beginBlock`)

The comment already admits it: "two rapid `setSettings()` calls inside one block are safe … three or more could race the copy". Knob drags at 30–60 Hz against 128-sample blocks are fine; automation, a preset load followed by a UI write, or a scripted sweep is not. A torn `circuit` used to select no switch case — the exact bug this change set out to remove.

**Fix:** a 4-slot ring with a write counter (or a genuinely atomic settings struct) instead of ping-pong.

## 3. What is genuinely good

- **Engine separation.** `engine/` is JUCE-free, header-only and unit-tested, which is why most of the correctness surface is testable without a device or host.
- **Project input hardening.** `ProjectJson` rejects non-JSON numbers, leading zeros, bad unicode escapes, depth > 256, > 1 M values and > 256 MB; `ProjectState::sanitize` clamps every field, drops unsafe `assetPath` values (CWE-22), caps plugin blobs at 2 MB and MIDI notes at 64 k; `MediaCollect` independently rejects `..` and `.` names. Better than most hobby DAWs.
- **Publishing pattern.** Retired-snapshot + block-counter sweeps in `AudioEngine` and `AuxBus`, publish-then-retire in the insert rack — the right shape, with DAW-10 as the one exception.
- **Third-party containment.** `HostedInsert::process` catches every exception from `processBlock`, clears the buffer and bypasses the slot; non-finite output is scrubbed; bus-layout negotiation is verified rather than assumed.
- **Plugin scanning** runs in a child process with a timeout and kills a hung worker, so a broken VST3 cannot wedge the app.
- **Bridge contract.** 51 routes in one table, extracted by `gen-native-routes.mjs`; `--check` passes, so the TypeScript vocabulary cannot drift from the C++ registrations.
- **UI.** `tsc` clean, 81/81 tests, 485 kB bundle (149 kB gzip), no `dangerouslySetInnerHTML`/`eval`, and a real timeout/watchdog story in `juce.ts`.

## 8. Status update — DAW-01 to DAW-17 fixed

All seventeen were repaired across `app/Source/AudioEngine.{h,cpp}`, `app/Source/ArrangeView.cpp`, `app/Source/WebViewBridge.cpp`, `app/Source/MainComponent.h`, `app/Source/TrackInsertRack.{h,cpp}`, `ui/src/App.tsx`, `ui/src/workspace/Workspace.tsx`, `ui/src/brand.css`, `engine/include/nc/engine/{Export,ProjectLimits,AnalogCharacter}.hpp`, plus the new root `LICENSE`, `README.md` and `THIRD-PARTY-NOTICES.md`, and verified:

- **DAW-01:** `StageStats::count` is now an enumerator (`enum { count = 8 };`) instead of a static data member in a local class.
- **DAW-02:** `analyzeVoiceFile` builds its `ClipState` up front (`isMidi = true`, `track`, `startBar = 1`, `lengthBars = 1`) and returns that clip on every error path — unreadable file, short read and no notes — so a failed transcription is an empty MIDI clip plus an error string, as `VoiceToMidiTests.cpp` requires.
- **DAW-03:** one `juce::MidiBuffer midiBlockScratch` member replaces the per-track local. `ensureSize` is called in both `audioDeviceAboutToStart` and `prepareForRender` (bounded at `maxMidiNotesPerClip * 8` bytes), and `renderBlock` now does `auto& midi = midiBlockScratch; midi.clear();` per track — `clear()` keeps capacity, so scheduling no longer allocates.
- **DAW-04:** `assetPeakEnvelope` now consults a bounded `peakEnvelopeCache` keyed by `(assetId, startFrame, lengthFrames, bins)`. A hit returns without touching samples; a miss scans once and stores. The cache is cleared by `addAsset` and capped at 2,048 entries (each 96 floats), so a drag that keeps changing the range cannot grow it without limit. Message-thread only, matching all call sites.
- **DAW-05:** a RAM-resident asset is now capped by *bytes*, not only by seconds at the file's rate. `ProjectLimits.hpp` adds `maxResidentAssetBytes` (512 MB) and `maxResidentAssetFrames(rate, channels)`; `loadAudioFile` and both branches of `processAsset` use it, so the audio-suite render no longer clamps at a hard-coded hour (a 1.4 GB allocation). `setSize` is wrapped in `catch (bad_alloc)` / `catch (length_error)`, and the reason is reported through `AudioEngine::lastAssetError()`, which the arrange view's import and recorded-take alerts now show. The streamed path is unchanged.
- **DAW-11:** `AnalogCharacter` now publishes into a four-slot ring with a monotonic `writeIndex` instead of ping-ponging two snapshots. `beginBlock()` reads the index, copies that slot, and re-reads the index; if a publish landed in between it takes the newer slot (bounded to four attempts, and even the fallback is one whole slot). Three writes inside one block — preset load, UI write, automation — leave the slot being copied untouched; the old comment admitting that "three or more could race" is gone.
- **DAW-12:** the missing distribution artefacts now exist. `LICENSE` is the GPL-3.0 text (copied from the vendored ChordStudio licence) because that is what the combined binaries already are while ChordStudio is statically linked; `THIRD-PARTY-NOTICES.md` records JUCE (GPL-3.0 or commercial), ChordStudio, the WebView2 SDK and the SIL-OFL `@fontsource` families; `README.md` covers build, tests and the licence position. The two Monotype faces were removed from `ui/src/fonts/`, the `@font-face` rule was dropped and the display lockup now uses Archivo Variable — `ui/dist` was rebuilt and the app re-linked, and the shipped executable no longer contains the font (a byte search for `motter-corpus-condensed` returns nothing). Choosing GPL-3.0 or buying a commercial ChordStudio licence remains the owner's decision; the files record the current, factual position.
- **DAW-13:** the documents now match the tree. `.planning/ROADMAP.md` is re-dated 2026-11-12 and records 168/168 native and 81/81 UI tests; Phase 1 (recording) is marked **DONE** with its evidence — both bridge routes exist, `App.tsx` wires `onRecord`, takes are placed through `ArrangeView::placeRecordedTake`, four `[record]` native tests and two UI tests cover it — and only the desktop capture with a real input device is left. `DAW_WORK_LOG.md` gains a close-out entry that supersedes the stale "ctest 165/165" line and names `mix_rack` (the suite that exposed DAW-02) as the excluded one. `AudioEngine.h` now says eight effects-only insert slots instead of "four user slots", and `ProjectState.hpp` says eight slots shown as two banks instead of "the four slots the browser can load into". `.planning/phases/01-audio-recording/PLAN.md`'s `160/160` expectation is corrected too.
- **DAW-17:** the diagnostics are out of the Release path. `StageStats` — the `NC_STAGE_TIMER` per-stage timer that caused DAW-01 — is deleted outright (its `dump()` was never called), together with the `TEMP DIAGNOSTIC` block in `restoreAudioSettings` that wrote `nc-restore-log.txt` on every start. The tone probe and the audio dump are now inside `#if JUCE_DEBUG`, with a Release stand-in whose fields are `constexpr` so the render-loop branches fold away; the device-start `audio-diag.txt` write is guarded the same way. Verified on the built binary: `NC_TEST_TONE_HZ`, `NC_AUDIO_DUMP`, `NC_STAGE_TIMER` and `nc-restore-log` appear **zero** times in `NCSound Music Hub.exe`.
- **DAW-16:** the replacement is now all-or-nothing. `setTimelineClips` validates the clips first, then asks the new `SpscQueue::spaceAvailable()` whether the clear plus every add fits; if not, it refuses the whole publish, leaves the engine's schedule and `timelineMirror` untouched, and records the reason in `lastTimelineError()`, which `ArrangeView` prints ("N CLIPS NOT SCHEDULED / THE ENGINE COMMAND QUEUE IS FULL…") instead of the misleading 1024-clip message. The mirror used to be cleared before the clear command went out, so a full rail left an empty timeline painted over a schedule that still played. New `[timeline]` suite (2 cases, 16 assertions): a publish that cannot fit reports the drop and leaves the mirror equal to the accepted schedule, and a refusal does not wedge the next, smaller publish.
- **DAW-15:** `handleApplyMixology` now takes the same guard as `runWrite`: it records `stateRevision.current` before the call and applies the reply through `applyState` only if no newer host push landed meanwhile, so a slow preset reply can no longer roll the screen back to older engine state. The report string is still returned either way — it describes what the host did, not what is on screen — and the redundant `setState`/`setTransport` pair is gone, since `applyState` bumps the revision and updates transport itself.
- **DAW-14:** the bundle's directory structure now travels with the resources. `juce_add_binary_data` flattens every source to a basename, so `app/WebResourcePaths.h.in` is filled by `app/CMakeLists.txt` with the relative path of every file in the same sorted list handed to `juce_add_binary_data`; `getWebResource()` matches the whole normalised path through `nc::web::findResourceIndex` (`app/Source/WebResourceLookup.h`), with the root alone serving `index.html`. It pairs the generated table with `namedResourceList`/`originalFilenames` by index and returns nothing (plus a debug assert) if the basenames ever disagree, so a build-system drift cannot quietly serve the wrong bytes. New `[webui]` suite (5 cases, 14 assertions) pins the rules: root and `/index.html` serve the shell, `/assets/index.html` and `/deep/nested/index.html` do not, same-named files in `assets/` and `other/` stay distinct, case/backslashes/query strings/absolute URLs are handled, and a `..` segment matches nothing.
- **DAW-09:** the workspace ceiling is now 64 in both places (`App.tsx`'s add-track guard and `Workspace.tsx`'s capacity/status), matching `nc::limits::maxTracks`; a 16-track default session no longer opens a workspace that refuses to grow past 8. No layout work was needed — the mixer strips scroll horizontally (`.ws-strips`, `grid-auto-flow: column`) and the arrangement maps `tracks` dynamically. The chrome test's expected status line moved to `2 OF 64 TRACKS`.
- **DAW-10:** retired processors now carry the block they were retired at (`RetiredProcessor { processor, retiredAtBlock }`) and `collectGarbage()` frees one only once `beginBlock()`'s counter has advanced two blocks — the same `retiredAtBlock + 2` rule the tempo/MIDI/automation snapshots and `AuxBus::collectRetired` use. `beginBlock()` increments the counter with `acq_rel`, so a sweep can no longer win the window before a callback reaches the old `audioInCallback` store. A `noCallbackCanRun` argument frees everything and is passed only by the destructor and `audioDeviceStopped()`; the insert tests pass it explicitly because no callback runs there.
- **DAW-07:** `webEditClip` parses every numeric patch field through a finite-checked helper, so a NaN can no longer reach a `(int)` cast. `startBar` and `lengthBars` are clamped to `1..maxBars`, then re-clamped as a pair so `startBar + lengthBars - 1` stays inside the timeline; `gainDb`, `fadeInBars` and `fadeOutBars` reject NaN too.
- **DAW-08:** the `transcribeClip` route no longer mixes the clip down on the message thread. `AudioEngine::runWithAssetSamples` resolves the range on the message thread and hands the worker the asset pointer and frame range; the mono copy happens on that thread. Assets are append-only and their buffers are immutable once added, so the pointer stays valid. `MainComponent::transcriptionInFlight` allows one job at a time and is cleared on the message thread when the job answers or when the spawn is refused.
- **DAW-06:** `renderToFile` no longer keeps the mix in RAM. Pass 1 renders into a `juce::TemporaryFile` beside the destination as interleaved float32 while feeding a new streaming `nc::engine::export_::LoudnessMeter` (same K-weighting, 400 ms / 75 % blocks, gates and 4x cubic true-peak scan; it keeps only a 400 ms ring). Pass 2 reads that file back in 4,096-frame blocks, applies the normalisation gain, measures the gained signal with a second meter, dithers once and writes. Peak RAM is a 512-frame render block plus ~0.3 MB of metering state at 48 kHz, instead of 690 MB (30 min / 48 kHz) to 2.7 GB (192 kHz). A temporary-file failure reports instead of throwing.
