## 2. Recording — root cause and fix

The `[mock]` hardware tests aborted with `0xC0000409` (`ucrtbase`, `FAST_FAIL_FATAL_APP_EXIT`) and the
take test left a **104-byte WAV** (RIFF header + `JUNK`, no audio).

Root cause: `AudioEngine::startRecording(folder, error)` created a `juce::FileOutputStream`, passed
the raw pointer to `AudioFormatWriter::createWriterFor`, and left the `unique_ptr` owning it.
`createWriterFor` takes ownership, so the stream was deleted when the loop iteration ended; the
writer thread then flushed into a dead stream. The crash happened in
`AudioFormatWriter::ThreadedWriter` teardown, which is why it looked like a test-framework abort.

Fixed:

- `stream.release()` after a successful `createWriterFor` (the writer owns it from then on).
- `capture.writerThread` (the `TimeSliceThread` behind every `ThreadedWriter`) is started in the
  `AudioEngine` constructor and stopped in the destructor. It had never been started, so queued
  audio could not drain.
- The callback no longer walks `capture.threadedTakes`; one writer pointer per track is published in
  `capture.recordWriters`, so `startRecording`/`stopRecording` cannot mutate a list the audio thread
  is reading.
- Streamed takes skip the 3-minute RAM buffer allocation (`beginRecording(error, false)`); the RAM
  path keeps it. This removes ~69 MB per armed track from folder recordings.
- Disk FIFO overflow now increments `recordOverflows()` through `capture.overflowCount`; it was
  previously invisible.
- `recordFramesWritten` is atomic, and `stopRecording` waits two blocks whenever either the device or
  `processBlockForTesting` may have a callback in flight.

New regression test: `RecordingTests.cpp` → **"a streamed take writes its audio to disk"**. It opens
the folder path, drives two blocks through `processBlockForTesting`, and asserts the WAV contains both
blocks and the expected sample value. This is the test that would have caught the original bug.

## 5. Engine and session behaviour

- **Autopilot off the message thread:** the `mixologyAutopilot` route starts a worker, refuses a
  second pass, and returns through `MessageManager::callAsync`. `MainComponent::~MainComponent()`
  joins the worker before the engine dies. `runMixologyAutopilot` uses a per-run temp directory that
  is deleted on every return, and `measureWithEarshot` kills a child after 120 s. The Earshot lookup is
  `EARSHOT_HOME`, then `<user app data>/NCSound/earshot`, then the legacy dev paths.
- **Streaming cache:** each slot records the transport block it was published at; `serviceStreaming`
  skips a refill of a slot published fewer than two blocks ago. This closes the race in
  `docs/engine-components-audit.md` item 1.
- **MixRack coefficients:** `MixRackChannel::beginBlock()` rebuilds the strip once per block; the
  render pass calls it before the sample loop. Direct `processSample` callers keep the revision check
  so tests and offline helpers still work. This removes mid-block filter reconfiguration.
- **Dirty tracking / autosave:** `AudioEngine::sessionFingerprint()` hashes active tracks, gain, pan,
  sends, width, mute/solo, automation read, instrument names, all eight insert names/bypass flags,
  channel and master rack revisions, master plugin, BPM, loop, markers, master gain/dim/mono and a
  session revision counter. `MainComponent::markDirty()` and `hasUnsavedSessionWork()` use it, so
  mix-only work now journals and prompts.
- **MIDI learn:** the pending queue is capped at 1,024 entries (newest kept) so a controller cannot
  grow memory without bound while the message thread is blocked.
- **Rack overlays:** `aria-modal`, Escape and backdrop close for the channel strip and master rack.
